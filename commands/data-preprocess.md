## What this command does

Builds and runs a preprocessing pipeline on the ingested data.

Ask:
1. What modality? (EEG, iEEG, fMRI, other)
2. What is the path to the data?
3. What preprocessing steps are needed? Or should it be a standard pipeline for the modality?
4. Should preprocessing decisions be made blind to group and condition labels? (skill → *Blind preprocessing*)

---

## Standard EEG pipeline

1. Load data (MNE Raw)
2. Filter (bandpass, notch)
3. Re-reference (average, linked mastoids, or REST)
4. Mark bad channels
5. ICA — fit, inspect components, remove artifacts (EOG, ECG); decisions go into the components file the pipeline reads (skill → *ICA decisions*)
6. Interpolate bad channels
7. Epoch around events
8. Baseline correction
9. Reject bad epochs
10. Save preprocessed epochs, plus one QC JSON per subject (skill → *QC JSON and the QC table*)

Document the pipeline parameters in `preprocess-config.md` in `.neuroflow/data-preprocess/`. Write the pipeline script to `output_path` (from `.neuroflow/data-preprocess/flow.md`, default: `scripts/preprocessing/`) — not inside `.neuroflow/`. The script records its own provenance with `nf_provenance` (skill → *Provenance, long runs and HPC*).

<!-- nf-rule: LOGIN-NODE -->
**Long runs and HPC:** runs longer than ~10 minutes follow the skill's *Provenance, long runs and HPC* (registry: `.neuroflow/data-preprocess/runs.md`); on a cluster the pipeline runs as a job, never on the login node.

## At end

- Save `preprocess-report.md` — parameters used, bad channels, ICA components removed, epoch rejection rate, and the subject-level QC table generated by `qc_table.py` (never retyped), with a note on every flagged subject and every exclusion decision
- **Reproducibility manifest** — `environment.md` next to the pipeline script in `output_path`, plus one run record per run in `provenance/`, both written by `nf_provenance` as the pipeline runs: Python version, exact versions of every imported package, OS, the random seeds the script declares, and the git commit with a dirty flag. Never write or edit them by hand; rerunning the pipeline regenerates `environment.md`, so it always answers "which versions produced these outputs". A MATLAB or R pipeline is wrapped with `nf_provenance.py record` and states its own versions (`ver`, `sessionInfo()`)
- Update `.neuroflow/data-preprocess/flow.md`
- Append to `.neuroflow/sessions/YYYY-MM-DD.md`
- Update `active_phase` in `project_config.md` if the phase changed
